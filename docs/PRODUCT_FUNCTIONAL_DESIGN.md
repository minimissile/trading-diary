# 交易日记：产品功能设计

> 版本：v0.1 · 2026-08-25  
> 产品形态：Windows / macOS 本地优先桌面应用  
> 产品边界：帮助用户执行自己的交易计划和复盘决策过程，不提供个股推荐，不自动下单。

## 1. 产品定位

### 一句话定义

一款把“交易计划 → 买卖点提醒 → 成交记录 → 单笔复盘 → 周期改进”串成闭环的个人投资工作台。

### 核心问题

多数交易记录工具只回答“赚了多少”，行情工具只回答“现在多少钱”，但用户真正需要改进的是：

- 买入前是否写清了逻辑、失效条件和风险预算。
- 价格到达关键位置时，能否看到原计划并按规则行动。
- 交易结束后，能否区分“结果不好”和“过程做错”。
- 多次复盘发现的问题，能否变成下一次交易前的检查项和提醒。

因此产品的核心价值不是预测涨跌，而是**提醒用户执行自己的计划，并用证据改进决策质量**。

### 目标用户

首版服务于有一定交易频率、愿意复盘的个人投资者，默认适配 A 股交易语义，同时在数据模型中兼容港股、美股、ETF、基金和加密资产。首版不面向高频交易、机构协作和量化策略回测用户。

### 产品原则

1. **计划先于提醒**：每个买卖点提醒尽量关联一份交易计划，避免脱离上下文的价格闹钟。
2. **过程与结果分开**：盈利不等于执行正确，亏损也不等于计划错误。
3. **自动记录事实，用户解释原因**：成交、盈亏、持仓天数自动算；判断、情绪和教训由用户填写。
4. **提醒必须可行动**：每次提醒都带条件、原计划、风险信息和下一步动作。
5. **本地优先、可导出**：核心记录和附件默认保存在本机，用户始终能导出自己的数据。
6. **不制造交易冲动**：不做收益排行榜、连续打卡、刺激性推送和“机会推荐”。

## 2. 核心闭环

```mermaid
flowchart LR
  A[创建交易计划] --> B[生成买卖点提醒]
  B --> C[触发时回看计划]
  C --> D[记录或导入成交]
  D --> E[完成单笔复盘]
  E --> F[周/月度复盘]
  F --> G[沉淀规则与检查项]
  G --> A
```

闭环中的最小业务单位不是单条成交，而是一个**交易回合**：围绕同一标的、同一方向和同一交易逻辑的一组买入、加仓、减仓、卖出记录。这样才能正确处理分批建仓和分批退出。

## 3. 信息架构

主导航按用户任务而不是数据类型组织：

| 一级入口   | 回答的问题               | 主要内容                                       |
| ---------- | ------------------------ | ---------------------------------------------- |
| 今日       | 今天最需要处理什么？     | 已触发提醒、临近计划、待复盘交易、数据同步状态 |
| 计划       | 我准备在什么条件下行动？ | 观察清单、交易计划、入场/退出条件、风险预算    |
| 提醒       | 哪些条件正在监控？       | 价格、时间、持仓风险和复盘提醒；触发历史       |
| 日记       | 我实际做了什么？         | 成交记录、交易回合、证据时间线、单笔复盘       |
| 分析       | 哪类行为有效或有害？     | 绩效、执行质量、错误成本、策略与标签对比       |
| 数据与设置 | 数据从哪里来、如何保护？ | CSV 导入、行情源、通知、备份、市场与费用规则   |

默认首页为“今日”，而不是收益仪表盘。首页按优先级只呈现四类行动：

1. 已触发但未处理的买卖点提醒。
2. 今日到期或临近触发的交易计划。
3. 已结束但尚未复盘的交易回合。
4. 行情过期、同步失败、通知权限关闭等数据风险。

## 4. 功能模块

### 4.1 首次使用与数据接入

#### 首次设置

- 选择主要市场、时区和交易日历。
- 设置中国市场红涨绿跌或国际市场绿涨红跌。
- 设置默认手续费、滑点和账户币种。
- 请求系统通知权限，并提供一次测试通知。
- 选择“从空白开始”“导入 CSV”“先体验示例数据”。

#### 成交录入

首版支持两种方式：

- **手工录入**：标的、方向、成交时间、数量、价格、手续费、账户、备注。
- **CSV 导入向导**：上传文件 → 自动识别列 → 用户确认映射 → 预览异常 → 导入。

导入必须具备：

- 以账户、订单号、成交时间、标的、方向、数量和价格生成幂等指纹，重复导入不产生重复成交。
- 原始行与标准化结果都保留，方便追溯和修正。
- 对未知代码、缺少时区、数量为负、费用异常等问题逐行提示。
- 导入完成后自动建议可合并的交易回合，但由用户确认。

券商账号直连放在后续版本；首版不以接入券商数量作为价值核心。

### 4.2 观察清单与标的详情

观察清单服务于“准备行动”，不是简单自选股列表。

每个标的卡片显示：

- 最新价、涨跌幅、行情更新时间和数据源。
- 当前计划状态：草稿、等待入场、持仓中、等待退出、已失效。
- 最近的触发条件和距离，例如“距入场区间上沿 2.3%”。
- 是否持仓、当前成本和风险暴露。
- 最近一次复盘结论和需要避免的错误标签。

标的详情包含四条时间线：价格关键点、计划版本、提醒触发、成交与复盘。用户应能回答“当时我知道什么、计划什么、实际做了什么”。

### 4.3 交易计划

交易计划分为必填区和增强区，避免填写负担过重。

#### 必填区

- 标的、方向（做多/做空；不支持的市场隐藏做空）。
- 计划类型：突破、回踩、趋势、反转、事件、价值/定投、自定义。
- 一句话交易逻辑。
- 入场条件：价格点位或区间，可附加时间有效期。
- 失效条件：止损价、逻辑失效描述或两者之一。
- 目标仓位或最大可承受亏损金额。

#### 增强区

- 分批入场和分批退出阶梯。
- 目标价、预期盈亏比、跟踪止损规则。
- 大盘/行业前提、财报或事件日期。
- 交易前检查清单。
- 截图、图片和文字证据。
- 策略、情绪预期、来源和自定义标签。

#### 风险计算器

输入账户权益、计划入场价、止损价和单笔风险比例后，计算建议数量、最大亏损和预期 R 倍数。结果只作为计划辅助，不生成交易建议。

#### 计划版本

计划激活后，每次修改保留版本和时间。触发提醒时展示当时有效的版本，防止用户在结果出现后改写原计划。

### 4.4 买卖点提醒中心

提醒是产品的核心执行层，共四类：

| 类型         | 典型条件                                 | 首版优先级 |
| ------------ | ---------------------------------------- | ---------- |
| 价格提醒     | 上穿/下穿某价格，进入/离开价格区间       | P0         |
| 时间提醒     | 某时刻、开盘前、收盘后、计划到期前       | P0         |
| 计划提醒     | 入场后待补止损、成交后待复盘、计划将过期 | P0         |
| 持仓风险提醒 | 浮亏、回撤、持仓天数、仓位集中度超过阈值 | P1         |

#### 价格提醒规则

- 条件支持“上穿”“下穿”“进入区间”“离开区间”，不只支持“等于某价格”。
- 展示行情源、最近更新时间和延迟属性；行情过期时不伪装成实时提醒。
- 通过回差阈值和冷却时间防止价格在临界点波动时重复轰炸。
- 断网期间保留最后状态；恢复连接后只对仍有意义的条件补触发，并标注“离线期间发生”。
- 计划失效、标的停牌、合约到期或用户清仓时，提示用户停用关联提醒。

#### 提醒生命周期

`草稿 → 监控中 → 已触发 → 已确认 / 已稍后提醒 / 已完成 → 已过期或已停用`

每条通知至少包含：标的、触发条件、当前值、行情时间、计划摘要和风险边界。通知动作提供：

- 打开计划。
- 10 分钟 / 1 小时 / 下个交易时段提醒。
- 标记已处理。

系统通知不能直接下单，也不使用“立即买入”“强烈卖出”等诱导语言。

### 4.5 交易日记与单笔复盘

#### 自动事实区

- 交易回合的加权买入价、加权卖出价、数量和费用。
- 已实现盈亏、收益率、持仓时长、计划风险 R 和实际 R。
- 是否有计划、是否按计划入场/止损/退出。
- 分批操作时间线。

首版没有可靠分钟级行情时，不计算 MAE/MFE，避免生成看似精确但错误的数据；接入历史行情后再加入最大有利/不利波动。

#### 复盘问答区

采用短问题渐进填写，默认只要求五项：

1. 这笔交易原本要赚什么钱？
2. 实际入场是否符合计划？
3. 退出由规则触发，还是临时决定？
4. 做得最好和最需要改进的各是什么？
5. 下一次遇到同类场景，要增加或修改哪条规则？

#### 执行质量评分

使用独立维度而不是一个模糊总分：

- 计划完整度。
- 入场纪律。
- 风险控制。
- 退出纪律。
- 复盘证据完整度。

分数由可验证事实和用户确认共同组成。盈亏不进入纪律分，页面同时显示“结果”和“过程”，防止事后偏差。

#### 错误与亮点标签

内置标签包括追涨、过早入场、无计划交易、仓位过大、移动止损、过早止盈、报复性交易、忽略市场环境、严格执行、耐心等待等。用户可自定义标签。

一个关键指标是**错误成本**：比较实际结果与用户原计划可计算的结果，估算某类纪律错误造成的损失。该指标需明确标注为估算值。

### 4.6 周报、月报与策略分析

分析页先回答“行为是否改善”，再回答“收益是否提高”。

#### 总览指标

- 净收益、收益率、胜率、盈亏比、期望值、Profit Factor、最大回撤。
- 平均持仓时长、交易频率、手续费占比。
- 有计划交易占比、计划执行率、按时复盘率。
- 错误成本、冲动交易次数、重复错误趋势。

#### 对比维度

- 策略、标的、市场、方向、持仓周期、账户。
- 星期、交易时段、仓位区间。
- 是否有计划、执行评分、情绪、错误标签。

小样本必须显示样本数；样本过少时不给“该策略有效”之类结论，只提示数据不足。

#### 周期复盘流程

1. 自动汇总本周期交易事实。
2. 展示表现最好/最差的交易回合，但不只按盈亏排序，也按执行偏差排序。
3. 聚合最常见错误、错误成本和高质量行为。
4. 用户写下“继续做、停止做、开始做”各一项。
5. 将结论一键转成下周的交易前检查项或提醒规则。

### 4.7 规则库与交易前检查

规则库是复盘闭环的出口。规则可来自用户手工创建，也可由单笔/周期复盘转化。

规则分为：入场、仓位、止损、退出、市场环境、情绪和操作流程。每条规则包含：

- 规则内容和适用策略/市场。
- 触发检查的时机。
- 来源复盘和创建时间。
- 最近 30 次适用交易中的遵守率。

当用户准备激活新计划时，只展示与当前策略相关的 3–7 条规则，避免把检查清单变成形式主义。

### 4.8 数据、隐私与可靠性

- 核心数据默认保存在本机 SQLite；截图沿用现有内容哈希文件仓库。
- 支持完整备份、恢复，以及 CSV/JSON 导出。
- 行情 API 密钥保存到操作系统凭据仓库，不写入 SQLite。
- 所有金额使用定点小数或最小货币单位存储，禁止浮点累计。
- 时刻统一保存 UTC，同时记录交易所时区和原始时间语义。
- 删除账户前显示受影响的成交、计划和复盘数量，并提供备份入口。
- 页面常驻数据状态：实时/延迟/过期/离线；统计口径可查看。

## 5. 关键用户流程

### 流程 A：从想法到提醒

1. 用户在观察清单选择标的，点击“新建计划”。
2. 填写逻辑、入场区间、失效条件和风险预算。
3. 系统实时计算建议数量和预期 R。
4. 激活计划时自动生成入场、止损和到期提醒，用户可修改。
5. 价格进入区间后，系统通知并打开计划摘要，而非直接建议交易。
6. 用户选择“已成交”“稍后提醒”或“条件已失效”。

### 流程 B：从成交到单笔复盘

1. 手工录入或导入成交。
2. 系统匹配已有计划和交易回合；低置信度时请求用户确认。
3. 回合平仓后进入“待复盘”，次日或用户设定时间提醒。
4. 用户查看事实时间线、填写五个短问题并标注错误/亮点。
5. 将一条教训转成规则，交易回合状态变为“已复盘”。

### 流程 C：周复盘到下周行动

1. 每周最后一个交易日收盘后生成周报草稿。
2. 用户查看收益、过程指标和重复错误。
3. 选择一项继续、一项停止、一项开始。
4. 系统将选定动作写入规则库，并在下周相关计划激活前检查。

## 6. 领域模型

| 对象         | 作用                     | 关键关系                       |
| ------------ | ------------------------ | ------------------------------ |
| Account      | 账户与币种边界           | 拥有成交和持仓                 |
| Instrument   | 标准化标的               | 关联计划、提醒和成交           |
| Execution    | 单条成交事实             | 属于账户，可归入交易回合       |
| TradeEpisode | 一次完整交易回合         | 包含多条成交，关联一个主计划   |
| TradePlan    | 某次交易的意图和风险边界 | 有版本，可生成多个提醒         |
| AlertRule    | 可执行的监控条件         | 关联计划、标的或持仓           |
| AlertEvent   | 一次不可变的触发事实     | 记录行情值、时间和处理动作     |
| Review       | 单笔或周期复盘           | 关联回合，产出规则             |
| PlaybookRule | 可复用的行为规则         | 在新计划激活前检查             |
| Attachment   | 截图与证据               | 复用现有资产仓库，关联上述对象 |
| Tag          | 策略、错误、情绪等分类   | 用于筛选与分析                 |

必须把 `AlertRule` 与 `AlertEvent` 分开：前者可编辑、可重复监控，后者是不可修改的历史事实。必须把 `Execution` 与 `TradeEpisode` 分开：前者来自券商或用户输入，后者承载复盘语义。

## 7. MVP 范围

### P0：首个可用版本

- 本地账户、标的、手工成交和 CSV 导入。
- 交易回合自动归组与手工修正。
- 交易计划、版本记录和风险计算器。
- 一个可配置行情连接器，支持价格上穿/下穿/区间提醒。
- 时间、计划到期和待复盘提醒；系统通知与触发历史。
- 单笔复盘、错误/亮点标签、规则转化。
- 今日、计划、提醒、日记、基础分析五个核心页面。
- 收益与过程基础指标、CSV/JSON 导出、完整备份恢复。

### P1：形成复盘优势

- 历史行情、K 线关键点标注、MAE/MFE。
- 周报/月报、策略对比和错误成本。
- 持仓风险与组合集中度提醒。
- 规则库遵守率和上下文检查清单。
- 更多 CSV 模板和券商只读同步。

### P2：谨慎扩展

- 多设备加密同步。
- 自定义公式提醒和策略模板。
- 事件日历、财报和公司行动提醒。
- AI 辅助归纳复盘，但必须引用用户原始记录，且不得生成买卖建议。

### 明确不做

- 自动下单、跟单、荐股和收益承诺。
- 首版实时资讯流、社区、排行榜和策略市场。
- 在缺少可靠行情数据时伪造实时技术指标。
- 用 AI 自动替用户填写交易逻辑或事后美化计划。

## 8. 首版验收标准

1. 新用户在 10 分钟内可完成账户创建、录入一笔历史交易并完成一次复盘。
2. 用户能在 3 分钟内创建含入场、失效条件和风险预算的计划并激活提醒。
3. 同一 CSV 重复导入不会新增重复成交，并能定位异常行。
4. 分批买入和卖出可以组成一个交易回合，盈亏和费用计算正确。
5. 价格穿越阈值只生成一次有效事件；在回差重置前不会重复通知。
6. 提醒详情能看到触发时的行情时间、计划版本和风险边界。
7. 断网、行情过期或通知权限关闭时，产品显著展示状态且不声称实时。
8. 盈亏和执行评分在界面上分栏展示，盈利不会自动得到高执行分。
9. 复盘结论可一键生成规则，并在下一份相关计划激活前出现。
10. 用户可导出全部核心数据和附件索引，并能从备份恢复。

## 9. 产品效果指标

首版不以交易收益作为唯一成功指标，因为收益受市场环境和样本周期影响。更可靠的产品指标是：

- 激活计划中包含失效条件的比例。
- 提醒触发后被查看或处理的比例。
- 平仓后 48 小时内完成复盘的比例。
- 有计划交易占全部交易的比例。
- 同类错误在后续 20 次交易中的复发率。
- 周复盘结论转为规则、且后续被实际检查的比例。

## 10. 与现有工程的衔接

当前工程已经具备 Electron 安全边界、本地 SQLite、后台任务、第三方连接器契约、图片仓库和系统更新能力，适合该产品的本地优先方向。建议开发顺序为：

1. 扩充领域数据库：账户、标的、成交、交易回合、计划、提醒、复盘与规则。
2. 建立成交导入和回合归组服务，先保证事实数据可靠。
3. 建立计划与提醒状态机，并接入一个行情源和系统通知。
4. 将当前冒烟首页替换为“今日”工作台。
5. 完成单笔复盘，再扩展基础分析和周期复盘。

现有图片仓库可直接承载交易截图、计划证据和复盘附件；现有 `jobs` 表可承载行情轮询、CSV 导入、提醒检测和周期报告任务；现有 `provider_connections` 可承载行情及后续券商连接器配置。
