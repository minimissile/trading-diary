# 公共 UI 组件规范

以“股息与分红”精修样板为基准，统一公共组件、工作区布局及浮层。以下记录当前实现，不将仅调整主题的页面描述为业务重构。

## 维护入口

- `src/renderer/theme/theme-config.json`：Ant Design 运行时及静态样式的唯一主题源。
- `npm run theme:generate`：同时生成 `antd-theme.css` 和 `ui-tokens.css`，不要手工编辑生成文件。
- `src/renderer/styles/ui-components.css`：公共组件补充样式及组件样板布局。
- 开发路由 `#/dev/ui-components`：实际组件与交互状态样板，生产版本无该路由。
- `dividends.css`：分红业务布局与点亮墙，基础配色引用公共变量。

## 使用方式

优先直接使用 Ant Design 组件，无需再次套壳。不要在业务页重新设置全局 `.ant-*` 规则，不要用 `!important` 掩盖主题冲突。

- 主操作：`<Button type="primary">`。
- 次重点操作：`<Button className="ui-button-secondary">`。
- 方形图标操作：`<Button className="ui-icon-button" aria-label="操作名称" icon={...}>`。
- 卡片：`Card` 或 `.ui-panel`，不叠加双层外边框。
- 列表辅助文字：`.ui-cell-secondary`，顶部间距 2px。
- 成功、警告、处理中、失败分别使用 Tag 的 `success`、`warning`、`processing`、`error`。
- 数值动画沿用 `AnimatedValueDisplay`，跨 Tab 缓存必须提供唯一 `cacheKey`。
- 表单校验使用组件的 `status` / Form 验证状态，不覆盖状态边框；禁用与加载交给组件处理。

背景默认关闭；启用背景时卡片沿用 `--workspace-panel-glass`。交易涨跌色是独立业务语义，本轮未改红涨绿跌规则。

## 已接入的工作区

应用框架统一使用 72px 顶栏、36px 顶栏控件、青碧选中导航和暖金记录成交按钮；默认使用实色，开启背景时接入统一的石墨色玻璃层。

持仓中心、计划工作台和交易日记的页面细节在 `workspace-refinement.css` 中维护：统一页面间距、16px 主卡片、直角内部数据区、持仓表格操作按钮和复盘笔记换行。公共框架在 `yingji-glass.css` 中维护，分红页不再单独覆盖侧栏或顶栏尺寸。

## 页面结构样板

- 持仓中心：`positions.css` 配合 `PositionsPage.tsx`，资产概览突出市值与盈亏，同步信息和分析入口置于概览底栏；持仓明细有独立分类和搜索区。搜索只筛选列表，资产统计保持按账户和分类计算。
- 计划工作台：`plans.css` 配合 `PlansPage.tsx`，执行阶段概览可筛选待激活、待入场和持仓中计划；列表提供名称／代码搜索，单张计划按交易逻辑、关键价位与风险、下一步操作分区。空状态区分首次使用、阶段为空和搜索无结果。

这两个页面的结构样式在公共组件之后加载；继续使用公共主题变量和可选背景面板，不重新定义全局控件主题。

交易日记由 `journal.css` 维护页面结构：复盘记录、待复盘、持仓回合三种视图独立展示；搜索覆盖标的、标题、总结与规则且不改变汇总统计。待复盘包含已平仓回合和已结束计划，入口沿用原复盘表单预填；成交时间线默认折叠，已完成复盘以结果数据、总结、下一次规则分区展示。

自选观察池由 `watchlist.css` 维护：研究说明与行情列表分区，研究要点默认折叠；分类和名称／代码搜索集中在列表工具栏，空结果可清除搜索。保留三类观察池的指标口径，行情请求失败显示错误与重试入口，详情抽屉沿用公共主题。

提醒中心由 `alerts.css` 维护：默认展示待处理提醒，监控中、历史和触发记录独立筛选，搜索覆盖代码与名称。手动价格检查默认折叠，明确说明检查可能触发系统通知；提醒状态变更沿用既有流程。

## 其余工作区

`library-pages.css` 管理以下页面的布局细节，继续复用公共主题：

- 规则库：分类、状态和内容搜索，规则内容与管理操作分区。
- 账户管理：账户搜索、归档筛选下沉到列表，账户身份与持仓数字分层。
- 复盘分析：交易结果与计划／纪律指标分区，过程占比采用横向进度。
- 成交导入：每次只呈现当前步骤，预览和完成页独立，完成页不保留确认导入按钮。
- 数据设置：分类定位栏，保持设置表单状态和既有保存流程。
- 首页：执行队列优先独占一行，其余面板按工作流程排列，取消固定网格行高；原有示例看板明确标注示例。
- 定投：关键汇总保留在首屏，连续执行记录可展开，行操作沿用公共方形按钮。
- LOF：扫描和规则操作归入观察区，监控与市场结果保留独立视图。

关于页面统一基础面板、间距与主题，未改动业务内容。

持仓二级页结构：历史持仓的年度筛选、搜索与记录列表归入独立面板，统计口径可展开；两种记录表格分别使用自己的数据类型。收益日历将月份选择放进日历标题栏，统计窗口移到底栏，首屏汇总保留月收益、有效交易日和分红贡献。

## 弹窗与生命周期

- `ui-components.css` 统一 Portal 弹窗、抽屉、表单及确认框。弹窗 20px 内边距，表单项 16px 间距、标签下方 6px，底栏以单条 1px 分隔线和 8px 按钮间距组织。
- 交易、定投、分红方式及流水浮层每次打开建立独立编辑状态，切换记录通过稳定记录 ID 重建，取消后重开不遗留旧值。
- 激活计划的规则清单读取失败时显示重试，加载和失败状态禁止提交；读取失败不等同于“没有规则”。
- 搜索清空、切换市场范围和卸载会取消待发送请求，过期结果不能重新填回建议列表。

## 样板与业务边界

首页执行队列接入真实数据；原有风险预算、阶段／时间线、复盘摘要、规则检查和数据状态仍含示例内容，界面明确标注。完成布局精修不代表这些区域已接入真实业务数据。

## 检查方式

- `npm run typecheck` 同时检查主进程、服务和页面；`npm run lint` 检查产品源码，排除外部 Skill 模板。
- `npm test` 运行离线确定性回归，导入测试模拟行情依赖；`npm run test:live` 单独运行需要真实行情的集成测试。
- 本机数据库集成测试仅在显式设置 `TRADING_DIARY_TEST_DB` 后启用。需要迁移的测试先创建 SQLite 只读备份，绝不在原数据库上执行迁移。
- 浏览器验收必须检查实际计算样式：主色 #116976、默认页面 #0e181f、面板 #16242d；开启背景后主色不变，恢复默认移除 `data-background` 并还原实色。
